fmIDE → a live-formula Excel workbook

1. Load an fmIDE model

Save a document in fmIDE (File → Save, a .fmide file), or export a system ("Save System" or "Export Workspace"), and load it here — or try the built-in sample to see how the tool works. Use "Export Workspace" (not just "Save System") if you want rectangles using fmIDE's shared "Inputs" format to carry that formatting into Excel.

Format roles

Every cell in the workbook takes its fill, font colour and border from one of these roles. Edit them in fmIDE's Formats manager (they travel in the exported JSON) — including which cell sides get a border and whether to use Excel's default font size. A rectangle's own 🎨 format still sets its number format, weight and size.

3. Tabs

One tab per fmIDE canvas by default. Rename, reorder, add, or delete tabs — rows are assigned to tabs below.

Tab nameRows

Every input rectangle (no incoming arrow) gets a row on this tab holding its typed numbers. Its original row stays where it is and links to it (green font). Rename, include/exclude and "Constant" stay in sync between the two. Tick "scenarios" on a row of this tab (Rows panel) to give that input several scenarios; a Scenarios tab then picks which one applies to each.

4. Rows

Every value rectangle becomes one labeled row. Operators, aliases, and period-shift nodes are inlined into formulas automatically — they don't get their own row (a rectangle fed through an alias points straight at the alias's source; a rectangle fed through a period-shift points straight at the shifted source, in the shifted period's column). A Block instance is unpacked: its definition canvas's own rectangles each get a row too, once per instance (a separate "Block instance —" group below, one per instance, since two instances of the same block compute independently and need independent cells) — a rectangle marked as a Block Input port inside the block is itself inlined, resolving straight to whatever's wired into that instance's port (or to 0 if the port is left unwired), the same way an alias is inlined. Assign each row's tab, section, order, and label; uncheck "Include" to skip a rectangle entirely. For a true input rectangle that's really just formula plumbing (a sign flip, a unit-scale factor like ×1000) rather than a labeled assumption, check "Constant" to splice its value directly into every formula that references it instead of giving it a row of its own — this works inside an unpacked block instance too. A rectangle marked as a Block Input or Block Output in fmIDE's Block feature shows a small "Block In" / "Block Out" tag next to its type, so you can see fmIDE's own port role — this is separate from the Input/Calc/Output section below, which is just this tool's own edge-based placement. To reorder many rows at once, or move a batch to a different tab or section, check the leftmost box on each row you want and use the bar that appears above the table — "Move Up/Down" nudges the whole selection by one slot, "Move to Top/Bottom" sends it to the edge of its group, and "Move to" relocates the whole selection to any tab (and section, if sections are enforced) you pick. Uncheck "Enforce Input / Calc / Output sections" below to stop treating those as hard bands in the generated sheet — a row's section then stays as an informational tag only, and rows in a tab are freely ordered as one flat list; use a Custom / Label row for any banner you still want. "Tree View" shows every row assigned to each tab — including an excluded or "Constant" one, dimmed, so it stays reachable — as one flat, clickable list: click to select a row, Ctrl/Cmd-click to add or remove one, Shift-click to select a range. From there, the bar above the list can set Include or Constant for every row in the selection at once (custom rows and ineligible rows are skipped automatically), and double-clicking a single row's label lets you rename just that one row in place.

5. Generate

Known limitations: a block instance's own compact node never gets a row — it's fully unpacked into its own "Block instance —" group instead (see the Rows panel above), so map/rename/reorder its rows there like any other. A vertical block instance (fmIDE's Vertical Block feature) is unpacked once per vintage/run — a "V1", "V2", … tagged copy of every internal row per period in the timeline — plus one "Σ Total"-tagged row per output port that reduces all those vintages back into the single value the rest of the model sees, via SUM/MAX/MIN/AVERAGE/PRODUCT matching that output's reducer (default sum); this is exactly a vintage/waterfall schedule with a Total row underneath, so with many periods a vertical block can add a lot of rows — reorder, rename, or exclude them like any other row. A block that instantiates itself, directly or indirectly, is skipped (avoids an infinite unpack). Formulas, number formats, and cell fill/border/font all carry through reliably. Excel recalculates formulas automatically when the file opens.

Your mapping autosaves in this browser and comes back whenever you load the same model again (even after Start Over). "Reset Mapping to Defaults" discards it for the loaded model — export it first if you might want it back.
