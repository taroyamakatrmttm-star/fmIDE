# Test groups: what each covers

Read when choosing or changing tests; `tests/SPEC.md` has every test (search it, don't read it whole). Moved word for word from `CLAUDE.md` (12 October 2026); keep it in step with the code, as `CLAUDE.md` asks.

- Phase E1 operators: agreement samples `agreement/operators-e1*.json` (group 17), the catalogue and fmIDE through `window.fm` (group 18), the exact Excel formulas and the list before download (group 19), the function syntax (group 20). Phase E2a's the same way: `agreement/operators-e2a.json` with Excel's answers pinned (17), the catalogue, commands and ribbon (18), the formulas (19), the syntax (20); and E2b's `choose`: `agreement/operators-e2b.json` (17), the catalogue, wiring, dots and setOperator (18), the formulas (19), the syntax (20).
- Function plugins: groups 17 and 19 cover ExcelExporter writing calls out (agreement samples `agreement/functions-*.json`, the exact formula text — LibreOffice can't show how Excel treats TRUE/FALSE — the Functions tab and Excel's formula limits). Test group 20 (`tests/20-functions.spec.js`) covers the parser (accepted and rejected text, limits, hostile text), the samples in `tests/fixtures/functions/` in Node and in fmIDE, and files carrying their definitions. Group 21 (`tests/21-functions-fmide.spec.js`) covers fmIDE's side: the library, the Functions manager and editor, the `fmIDE-functions` file, function nodes on the canvas (insert, drawing, wiring, updating, copy and paste), undo, the ribbon and macros.
- Library packs, where items came from (`origin`, the family-rule warnings) and the file limits: test group 22 (`tests/22-library-packs.spec.js`, `npm run test:library-packs`; sample `tests/fixtures/library/pack-v1.json`).
- The pack checker (`tools/check-pack.js`): test group 23 (`tests/23-pack-checker.spec.js`, `npm run test:pack-checker`; sample `tests/fixtures/library/check/`, saved by fmIDE). It reads packs with the shared code, so a change to how fmIDE reads packs, templates or functions is checked there too; anything fmIDE would drop or repair is an error in the checker.
- The library's rules (`tools/check-library.js`, `check-pack.js --library`): test group 24 (`tests/24-library-checker.spec.js`, `npm run test:library-checker`; sample library `tests/fixtures/library/sample-library/`, packs saved by fmIDE and records written by `--write-records`). With `--records-on-merge` (the library's pull-request check) a pull request's own missing records are notes, not errors: the library's CI writes them with `--write-records` once it is merged, for the account that opened it, so nobody edits the records by hand. The records (`families.json`, `authors.json`, `packs.json`) and `checker.json` are described in `docs/file-formats.md`; accounts are GitHub's numeric user ids. Pack text in its reports goes only through `quote()`, and the Markdown report keeps it inside one fenced block.
- The catalogue (`tools/build-library.js`): test group 25 (`tests/25-library-catalogue.spec.js`, `npm run test:library-catalogue`; samples `tests/fixtures/library/sample-library/` and `catalogue-hostile/`, a pack saved by fmIDE with markup in every text shown): the pages, downloads, `index.json`, escaping, the policy, a failing or missing library, and that the app's version and offline copy don't change.
- Browsing the library in fmIDE: test group 26 (`tests/26-library-browse.spec.js`, `npm run test:library-browse`; the sample libraries of group 25, served as a built site): the window, a tampered pack or list, hostile text, offline, no library, the single file making no request, the security policy, `window.fm` and macros. The build also reads its own `index.json` with the shared reader and stops if any pack would be left out.
- Touch (step 9): test group 27 (`tests/27-touch.spec.js`, `npm run test:touch`; 9c: the viewport line, the ribbon's arrows, dialogs at 1024 × 768 and 768 × 1024, the visible screen shrinking) and, for ExcelExporter's Tree view, group 30 (`tests/30-touch-excel.spec.js`, `npm run test:touch-excel`; the finger in `tests/helpers/touch.js`): Chromium with a touchscreen at 1024 × 768, real touch input through the Chrome DevTools Protocol (`Input.dispatchTouchEvent`), holds and double-taps included; each test checks the page saw touch, not a mouse. The mouse stays covered, unchanged, by every other group, which drive a real mouse (right-button drags included).
- Where new nodes go and the Macro Builder's next step: test group 28 (`tests/28-placement.spec.js`, `npm run test:placement`). `findFreeSpot` / `moveGroupToFreeSpot` (`06-align-marquee-computation.js`) place new nodes where they overlap nothing — `spawnPoint(w, h)` for commands, pickers and `fm.create…` without x/y, the default-offset `duplicate` / `aliasOf`, paste (the pasted group moves together), and the automatic plug aliases in `syncAutoConnections`; coordinates given explicitly are kept exactly. ExcelExporter sorts a new layout (`sortNewLayout`, calculation order with formula order within groups, both with and without sections); a saved one keeps its order.

(every `addWindowHelp` topic must exist), the touch menu's Help, ExcelExporter's panel (32); group 33 (`tests/33-tutorials.spec.js`): every tutorial played through with real clicks and typing, practice mode, the welcome card; group 34 (`tests/34-help-site.spec.js`, `npm run test:help-site`): the site's `/help` pages (What's new's too, H5c), their links, command names and tabs against fmIDE, escaping, the policy; group 35 (`tests/35-video-scripts.spec.js`, `npm run test:videos`): the video scripts and captions, and a real recording of the To Excel tutorial.
