# Help, tutorials and What's new

Loaded when a session works on help text, tutorials or the Help panel. Moved word for word from `CLAUDE.md` (12 October 2026); keep it in step with the code, as `CLAUDE.md` asks.

- **Help** (step 10, `docs/step10-help.md`; `01b-help.js`, the panel itself shared: `src/shared/help-panel.js` `createHelpPanel` and `help-panel.css`, pulled in by `// build:include shared/help-panel.js` and `<!-- build:css ../shared/help-panel.css -->`, by the owner's decision in H2): the help text is data in `src/help/fmide-help.js` (CC BY 4.0, pulled in by `// build:include help/fmide-help.js`): `HELP_GROUPS`, `HELP_TOPICS` (`{ id, group, title, keywords, summary, body }`; body blocks `p`, `steps`, `tip`, `see`; `{cmd:id}` in a text becomes a button that runs the command), `COMMAND_HELP` (one plain sentence per command) and `OPERATOR_HELP` (per operator id, for the Insert Operator commands; `commandHelpText(c)`). **Every new command needs a sentence** and a feature that changes needs its topic changed in the same pull request — test group 31 fails on a command without one or a topic naming a missing command or topic. The panel (`#helpPanel`, command `openHelp`, F1; ❓ `#rbHelp` beside the ribbon's search box; the View tab's Help group, added once to a customised ribbon, `ui.helpAdded`) sits beside the canvas (`body.help-open` narrows `#viewport`), is not a `.modal-overlay` so shortcuts keep working, and builds everything with `textContent`. **Its width** (H5a): ⤢ in its header (`.help-expand`) widens it to a reading view (two thirds of the window; from `HELP_WIDE_AT` 600 pixels it is `.wide`: larger text in a column), its left edge (`.help-resize`, pointer events) drags to any width, a double-click there goes back to 380; at least 300, always 200 pixels of the app left; the width is `--help-w`, kept through `options.size` (`cleanHelpSize`) — fmIDE's `ui.helpSize` (the person's own UI settings: never from an imported file, never in a Preferences file), ExcelExporter's `fmide-excel-help-size` (read later, `loadSize`). **What's new** (H5b): `options.whatsNew` — the updates are data, `src/help/fmide-whats-new.js` (`WHATS_NEW`, CC BY 4.0) and `src/excel-exporter/help/excel-whats-new.js` (`EXCEL_WHATS_NEW`, ExcelExporter's licence), `{ id, date, title, summary, what, why, how, notes, see }`, newest first, one per feature a person would notice (developer-only changes left out); shown above the tutorials (the three newest, Every update), a page per update, found by search; New = dated after the date seen (none seen: the newest's last 14 days), opening the list marks all seen; a dot (`.has-news`) on `#rbHelp` / `#btnHelp`; the date seen is fmIDE's `ui.whatsNewSeen` (own UI setting, never from an imported file) or ExcelExporter's `fmide-excel-whats-new-seen`; fmIDE's command `openWhatsNew` sits beside Help (`ui.whatsNewAdded`). **A change people will notice adds its What's new entry in the same pull request** (test group 43 checks the entries). Ribbon and Quick Access Toolbar buttons get fmIDE's own tip instead of a `title` (`setCommandTip`; `#commandTip`: name, shortcut, sentence, "Learn more (F1)" to `helpTopicForCommand`; F1 while it shows opens that topic); the Command Launcher lists topics (category Help, `help:<id>`). **Every new window gets a "?"**: `addWindowHelp(box, topicId)` in its builder (the panel then sits above the backdrop, `body.help-open .modal-overlay`); a node's touch menu has Help (`helpTopicForNode`). ExcelExporter's panel (`src/excel-exporter/js/09d-help.js`, its topics in `src/excel-exporter/help/excel-help.js` under its own licence, no `{cmd:}`): ❓ `#btnHelp`, F1, a "?" (`.panel-help`) beside each panel's heading. The same topics and tutorials are the site's `/help` pages (H4a, above); a change to the help text changes them too.
- **Tutorials** (step 10 H3, `01c-tutorials.js`; data `src/help/fmide-tutorials.js`, CC BY 4.0): `TUTORIALS` = `{ id, title, minutes, summary, topic, start?, steps }` (`start`: a small model as data, `practiceStartModel`), each step `{ id, text, point?, done? }` — `done` is a list of declarative checks (`rect`, `operator`, `periodShift`, `arrow` — ends may be `{ block }` or `{ fn, port }` — `value`, `periods`, `viewing`, `ownNumberIn`, `canvas`, `canvases`, `role`, `block`, `linkedTo`, `template`, `fn`, `functionNode`, `downloaded`, `openedExcel`; `checkPasses`), never code. Six tutorials: first-model, time, blocks, templates, functions, to-excel. `startTutorial(id)` enters **practice mode**: `snapshot()` of the model, undo history and `currentDoc` kept in `practice.saved`, a clean "Practice" canvas, `saveWorkspace()` does nothing (`inPractice()`), `runCommand` refuses `PRACTICE_BLOCKED` (New, Open, Save, Save As, Open Recent, Load/Add System, Import Workspace), `beforeunload` follows the saved document; `endTutorial()` restores all of it, and the library (`TEMPLATES`, `FUNCTIONS`, copied at the start) unless the last step's Keep box is ticked (`practice.keepLibrary`, `practiceLibraryAdded`). The coach card `#tutorialCard` (`data-tutorial`, `data-step`) and the ring `#tutorialPointer`; tutorials listed at the top of the Help panel (the shared panel's `homeTop`) and in the Command Launcher (`tut:<id>`). The welcome card `#welcomeCard` (bottom-right, blocks nothing, below windows, closed by the first change to the model — `pushHistory`) appears only when there is no autosave (`!restoredFromWorkspace`) and again from Help. **A new or changed tutorial step needs its action in `tests/helpers/tutorial-actions.js`** (shared by group 33 and the video recorder; clicks, typing and drags go through its `pace`), or group 33 fails. **Videos** (H4b): `npm run video-scripts` (`tools/video-scripts.js`: an opening line, a line per step — its `say`, an optional spoken line, where the card's words don't read well aloud; never the card's own buttons — and a closing line; `TUTORIAL_VIDEO` in `fmide-tutorials.js`) and `npm run record-tutorials` (`tools/record-tutorials.js`: plays each tutorial from `apps/` at a person's pace with a drawn pointer, no network, into `videos/<id>/` — `.webm` 1280 × 720, `.srt`, the timed script; To Excel also films ExcelExporter's window); `videos/` is never committed; GitHub's manual workflow **Record tutorial videos** (`.github/workflows/record-videos.yml`) makes them too.
