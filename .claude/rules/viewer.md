# fmShowcase, the showcase viewer

Loaded when a session works on the viewer, its read-only canvas or showcase files. The brief, approved by the owner on 27 October 2026 with all 11 of its recommendations, is `docs/viewer-brief.md`; its phases are V1 (done on branch `claude/viewer-v1`) to V6. Keep this file in step with the code, as `CLAUDE.md` asks.

- **What it is** (phases V1 and V2): `src/viewer/` → `apps/fmViewer.html`, the app called **fmShowcase** on screen (the file people open is "a viewer"). Apache 2.0 like fmGraph, with its licence notice at the top of `index.html`; its help text CC BY 4.0 (`src/help/viewer-help.js`). **Made only from fmGraph's board engine, `src/shared/` and its own: no ExcelExporter code, ever** (group 91 checks the build's list of its sources). **Read-only**: no editing control exists in the page (not hidden: absent), and nothing a visitor does changes the model (`fmViewer.modelText()` stays `modelTextAtLoad()`). It makes no network calls; what a visitor moved is kept on the device only (below).
- **The Board** (phase V2, 28 October 2026; `docs/viewer-brief.md`, "How V2 turned out"): the viewer takes in **fmGraph's board engine** by name in `js/01-core.js` (`// build:include fmgraph/js/…`, the list group 92's `ENGINE`: reading boards with the board file's upgrades, the calculation with sliders, every bar's and chart's figures and SVG, scenarios, Play's motion, A/B, Trace's reach, Biggest movers, the sample; `.claude/rules/fmgraph.md`) and **never one of fmGraph's other fragments**; its `js/06-board.js` defines the engine's **page interface** (`isPhone`, `renderBoard`, `updateValues`, `scheduleUpdate`, `paintMark`, `rectKeySwatch` / `chartKeySwatch` — plain marks, no colour box — `freeGridHook` — nothing — and in `07-scenarios-play.js` `renderCompareBar`, `renderPlayBar`, `paintPlay`), with fmGraph's class names (`.widget`, `.bar-widget`, `.chart-widget`, `.slider-widget`, `#board`, `#barList`, `.bar-chart-host`, `.chart-key`, `.bar-errors`) so the engine's painting works unchanged; the drawing's styles are `src/fmgraph/board.css`, the page's `src/viewer/board-view.css`. A showcase with boards (`boards`, an `fmIDE-graph-board` file — `readBoards`: limits, kind, upgrades, a newer one asked about, the template form refused, `cleanBoards`, empty boards left out), else a document's own `graphBoards` (the owner's choice 10), opens on the **Board** (`#boardView`; Board | Logic `#viewSwitch` `#tabBoard` / `#tabLogic`, on a phone `#phoneViews` at the bottom); without, on the Logic view as in V1. On it: board tabs `#boardTabs` (several boards), the scenario row `#scenarioRow` (`.scenario-btn` Base and each scenario, `.current`), `#scenarioNote`, the sliders `#sliderList` (each the shared phone slider, `sliderControls`, **kept in the author's range and steps** — a typed number too, `inRange`), Reset `#btnReset`, 📌 `#btnPinA`, Play `#playRow` (`#playFrom` / `#playTo`: Base, My sliders, the scenarios; `#btnPlay`; the showcase's `play` ends, "Base" or a scenario's name, `playFromShowcase`), the strips `#playBar` (■ Stop, ⇄ with reduced motion; Esc) and `#compareBar` (⇄ Swap, Unpin), Biggest movers `#moversPanel` (folded), and the bars and charts `#barList` (`barFrame` / `chartFrame`: title, 🔍 Trace, no other button). **A scenario is shown exactly** (`showScenarioExact`: the sliders where it has them and its numbers through `lookingAt`, inputs with no slider included; `shownScenario`); moving a slider leaves it (`leaveScenario`, Base plus the sliders; `#scenarioNote` names what it changed with no slider) — the owner's choice 3, the rule V4's Excel patch follows. **The periods** (choice 4): a showcase's `periods` are the boards' shared periods (`applyShowcasePeriods`) and the Logic view's period their first; without, the Logic view shows the boards' shared one period. **The Logic view follows the Board** (`setLogicNumbers` / `logicFollows`: `setResults` with the shown results; `state.moved`, the inputs moved, `.cv-node.moved` ringed, their numbers written in, the card "Moved on the Board, from …"). **Kept on the device** (`08-state.js`, `docs/architecture/storage.md`): database `fmShowcase`, key `viewer-state-<id>-<hash>` (`viewerStateKey`: the showcase's id and a hash of the showcase, model and boards), `{ v: 1, board, scenario, sliders }`, read back through `cleanViewerState` (numbers in range, the board and scenario known), written 300 ms after a change and on `pagehide`; Reset forgets it; Help's width `viewer-help-size`. **Help** (`09-help.js`): the shared panel, `?` `#btnHelp` or F1, topics only (no What's new, no manual link). **Try the sample** `#btnSample` (`10-sample.js`): fmGraph's `SAMPLE_MODEL` / `SAMPLE_BOARD` with two scenarios.
- **Opening** (`02-files.js`): a viewer made for one model carries its showcase and model in two data blocks, `<script type="application/json" id="showcase">` and `id="model"` (empty in the bare app; the browser runs no script of that type, so the site's policy hashes only the app's own script; when V3 writes them, every `<` is `<`). The bare app takes files dropped anywhere or chosen (`#fileInput`, `multiple`): a model (system or workspace, `readModelData` with the shared upgrades, a newer version after asking), a showcase (laid over the model open when alone), both at once; a recipe is refused ("for making many viewers"). Every file through `fileTextProblem` / `fileDataProblem` first.
- **The showcase** (`src/shared/showcase.js`, kind `fmIDE-showcase` version 1, `docs/file-formats.md`): `readShowcaseData` (kind, upgrades through `SHOWCASE_FORMATS` / `SHOWCASE_MIGRATIONS` — none yet — newer flagged, `recipe`), `cleanShowcase` (one model: `id` letters, digits and dashes up to 60, `title` 80, `description` 400, `author` 80, `licence` free text 60 — the owner's choice 8 — `mark` true unless `false`, `canvases.show` / `start`, `boards` an `fmIDE-graph-board` file kept as data and read by the Board (not the template form), `play`, `periods` a range from 0, `excel.file` through `showcaseFileName`), `cleanShowcaseRecipe` (`title` with `{model}`, `boards` the template form, `auto` sliders `inputs` / bars `outputs` / range 1–100), each `{ value, problems }` with every problem in plain words; `resolveShowcase(sc, canvases, periodCount)` the canvases shown (unknown ones left out and said), the start, the periods. **The canvas's numbers are for one fixed period, the first the showcase names** (the owner's choice 4, 27 October 2026: no period stepper; `state.period`, passed to `nodeTexts`, so another period is a small change); the card shows every period shown. "Hiding is not secrecy": a hidden canvas is only off the screen.
- **The read-only canvas** (`src/shared/canvas-view.js` and `.css`; the viewer only): `viewModel(system, presets)` (the shared IR, `evaluateModel`'s results — `setResults` swaps them, for V2's sliders — the canvases as the calculation sees them, `ir.order[i].raw`, so plug links and their automatic aliases are where fmIDE puts them; role styles from the presets, else `FORMAT_ROLES`), `canvasLayout(vm, canvasId)` (boxes and ports — a port's dot 8 in from the side, 11 down its row — and arrows with fmIDE's geometry; runs in Node), `nodeTexts(vm, canvasId, period)`, `drawCanvas(g, layout, texts)` (SVG by DOM calls and `textContent` only; colours through `safeColor`, font names a short pattern, sizes 6–72, borders solid / dashed / dotted), `canvasDefs(svg)`. Positions and sizes forced to numbers within ±100,000 (sizes 10–5,000, else fmIDE's default). Its exported names start `cv` where an app's might clash (`cvHasIncoming`, `cvIsInput`), since the apps share one scope (group 64).
- **Moved out of fmIDE for it** (unchanged, test written first in group 7-ui-fmide, "every kind of node and arrow keeps its place, size and value text", snapshot `fmide-every-kind.txt`): `src/shared/canvas-geometry.js` — `rectOf`, `borderPoint`, `edgePath`, `operatorPortsHeight`, `blockInstanceHeight`, `functionNodeHeight`, `portNodeWidth`, `PORT_HEADER_H`, `PORT_ROW_H` — and `src/shared/number-format.js` — `formatNum`, `formatByNumberFormat` (fmIDE's `formatNumForNode` still chooses the format), `shiftLabel`. fmIDE keeps measuring its port dots on screen (`getPortCanvasPos`); the viewer works them out, and group 91 compares the two.
- **The page** (`index.html`, `styles.css`, `js/01-core.js` … `05-api.js`): the title, description, author (`#showTitle`, `#showDescription`, `#showByline`), the canvas tabs `#canvasTabs` (a ☰ menu `#btnCanvasMenu` / `#canvasMenu` on a phone, `body.phone` from the shared `isPhoneScreen()`), the stage `#stage` with `#canvasSvg` / `#world`, + / − / Fit (`#btnZoomIn`, `#btnZoomOut`, `#btnFit`; keys + − 0), `#periodNote` ("Numbers for …"), a one-line hint, the card `#card` (`#cardTitle`, `#cardWhere`, `#cardBody`: "An input…", "How it is worked out" — the formula with names and with values, operators followed 3 deep, named inputs labelled, a period shift "in the period before", a function `Name(…)`, a block's output "Out of Block" — the values in each period shown, the inputs it reads as buttons, `.card-input`, going to them on their canvas, or "on a canvas not shown here"; from the bottom of the screen on a phone), and the mark `#mark` ("Made with fmIDE" as plain text, with the licence; `mark: false` hides it — a link only after the owner's name is out of the public places). Pan by a drag (`onPress` / `followPointer`, `pressDefault`), a tap opens a card, two fingers pinch (`cancelFingerActions`), the wheel zooms about the pointer, each canvas keeps its own view. The keys + − 0 work on the Logic view only. With no boards, the canvas's period is the first the showcase names (with boards, the Board's: above).
- **`window.fmViewer`** (`js/11-api.js`): `state()` (with `view`, `hasBoard`), `canvases()`, `showCanvas(id)`, `openCard(canvasId, nodeId)`, `closeCard()`, `goTo(canvasId, nodeId)`, `value(canvasId, nodeId, period)` (with the Board's sliders), `view()`, `fit()`, `layout()`, `modelText()`, `modelTextAtLoad()`; V2: `showView`, `board()`, `showBoard(i)`, `setSlider(idOrName, v)` (kept in range), `showScenario(name | 'Base')`, `reset()`, `play(from, to)` ("Base", "My sliders" or a scenario), `stopPlay()`, `stepPlay()`, `pinA()`, `unpinA()`, `swapA()`, `trace(id)`, `bar(id)`, `chart(id)` (the engine's `chartAnswer`, as `fmGraph.chart`), `movers(n)`, `trySample()`, `saveNow()`, `stateKey()`; V4 `excelBytes`.
- **On the site**: `/fmViewer.html`, not linked from anywhere, under its own security policy and in the offline copy (the owner's choice 2), so the owner can try it on an iPad or a phone after `npm run deploy`.
