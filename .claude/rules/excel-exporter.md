# ExcelExporter

Loaded when a session works on ExcelExporter. Moved word for word from `CLAUDE.md` (12 October 2026); keep it in step with the code, as `CLAUDE.md` asks.

**ExcelExporter's page** (step 14, `src/excel-exporter/index.html`, `09e-menus-and-settings.js`, `styles.css`): a dark top bar with ← Back to fmIDE, the model's name (`#modelName`), two menus — **File** (`#menuFile`: Open Model…, Load Sample Model, Paste JSON…, ↻ From fmIDE when fmIDE opened it, Start Over) and **Layout** (`#menuLayout`: Import / Export Mapping, Import / Export Module Layouts, 📎 Attach to Template… when fmIDE opened it, Excel Style…, Reset Mapping to Defaults…; the mapping items, `.needs-model`, off until a model is loaded) — then ⚙ Settings, ❓ Help and ⬇ Generate (`#btnGenerate`, off until a model is loaded). **Every new file action or reset goes in one of the two menus** (an item is a `role="menuitem"` button keeping its old id; `syncPageState()` says what depends on a model). ⚙ Settings (`#settingsModal`, not a page section) has the tabs Workbook (`#periodsPanel`: period labels, fallback number format, file name; off without a model) and Excel Style (`#excelStyleBlock`, with its Import / Export / Reset). Messages (`setStatus`, each with ×) sit in `#notices` under the top bar, with `#differencesPanel`. Before a model, the welcome screen (`#loadPanel`, the drop box, sample, Paste JSON… in `#pasteModal`); afterwards a file dropped anywhere opens. Loaded: `#afterLoad` is a sidebar (Tabs `#tabsPanel`, Inputs & scenarios `#inputsPanel`) beside Rows (`#rowsPanel`, the Tree first), stacked when the page itself is under 960 pixels (a container query, so Help open beside it counts). **Keep the page short on words**: a heading, at most a one-line note; explanations go in tooltips and the help topics (group 46 fails on a paragraph over 120 characters). Test helpers `menuCommand`, `openSettings`, `closeSettings` (`tests/helpers/excel.js`). **On a phone** (step 17 P3, `09h-phone.js`): `body.phone` from the shared `isPhoneScreen()`, decided once at start, unless ☰ → Full app (`fmide-excel-full-app`; 📱 Phone layout `#phoneLayoutBtn` back); one screen, `#phoneView` — before a model `#phoneStart` (Open a model file… `#phoneOpen`), with one `#phoneLoaded`: the workbook's tabs `#phoneTabs` (names from the workbook built without downloading it, `phoneSheets`, kept until the model or layout changes; row counts `tabRowCount`, as the Tabs panel; chart tabs "chart"), the file name `#phoneFileName` (`mapping.cfg.fileName`, saved with the layout) and ⬇ Make the workbook `#phoneMake` (`makeWorkbookOnPhone`: `XLSX.write` of `buildWorkbook()` through the shared `shareFiles`, the name made safe, `phoneWorkbookName`); messages and `#differencesPanel` as usual; ☰ `#phoneMenuBtn` / `#phoneMenu` (Open a model file…, ↻ From fmIDE when fmIDE opened it, Help, Full app); the menus, Settings, Help button, Generate and the page's panels hidden; `renderExcelPhone` from `syncPageState`. Test group 72.

**Sensitivity** (step 16, ExcelExporter's `09g-sensitivity.js`, `docs/step16-sensitivity.md`): the sidebar's Sensitivity panel (`#sensitivityPanel`: `#cfgSensEnabled`, the outputs `#sensOutputs` / `#sensOutputPick`, `#cfgSensPeriod`, `#cfgSensSteps`, the inputs `#sensVars` / `#sensVarPick` / `#btnSensAddAllVars`, `#sensStatus` saying why there will be no tab) keeps `mapping.cfg.sensitivity` (read through `cleanSensitivity`, rows checked by `reconcileSensitivity`; mapping file 3). An input can be moved only from the Inputs tab and not inside a block or on a canvas used as a block (`isSensitivityInputRow`); any rectangle row written can be watched (`isSensitivityOutputRow`). `sensitivityPlan()` says what the workbook holds; `buildCtx` gives a moved input without scenarios a Base row (`sensBase`), and its own row is `(base)*(1+% part)+amount part` from the Sensitivity tab (`sensitivityLayout`, worked out before any tab is written). `appendSensitivitySheet` writes the tab: C4 output, C5 period, C6 input moved (0 = none), C7 point, C8 the output now (`CHOOSE` / `INDEX`, never `OFFSET`), the outputs, the inputs (Change by, Low, High, Show — typed, changeable in Excel), one two-input Excel Data Table (the writer's `dataTable` cell; C7 the row input, C6 the column input) holding fmIDE's numbers (`sensitivityValues`: the shared IR with the input's numbers laid over its typed ones), and the Tornado (rank by `SUMPRODUCT`, equal swings in order) and Spider tables; `placeSensitivityCharts` adds the two charts (`sensitivityCharts`; `cfg.charts` `tabs` — chart tabs Tornado and Spider — or `sheet` — on the Sensitivity tab), and `#cfgSensCharts` chooses.

**Module layouts** (step 11b, ExcelExporter's `04b-module-layouts.js`): the layout of a module's tab — a canvas with `canvas.template.family`, its own tab `tab_<canvas id>` — is remembered per template family (`moduleLayouts`): the tab's name when renamed, the row order with sections on (`sectioned`) and off (`flat`), each row's section, own label, Include / Constant, own format and indent, and its custom rows, as references `r<n>` / `c<n>`. Rows are matched by rectangle name (capitals and outer spaces ignored; a name used twice on the canvas matches nothing — as fmIDE's `planCanvasUpdate`). **Remembered automatically**: `saveMapping` calls `rememberModuleLayouts`, which stores each module tab that differs from `moduleBaselines` (set at load, Reset and Forget). **Used only for a new layout** (`applyModuleLayouts` after `sortNewLayout`, at load without a saved layout and at Reset Mapping): a layout saved for the whole model always wins; unknown rectangles go in after the row they followed in the automatic sort (`mergeRememberedOrder`); a tab name already used elsewhere is not taken. Rows moved to another tab are not followed. **Block instance tabs** (step 11d): a module used as a block also remembers its instance tabs' layout, `instance` in the same entry (no tab name; rows matched by name and `copy` — a vintage, `total`, `shared` — `rowsByKey`, `instanceTabSpec`; a block inside the block not matched); an entry may hold only `instance` (`hasTabLayout` false: no module tab laid out); remembered and used like a module tab's (baselines keyed by tab id); Forget on an instance tab drops only `instance`; **Lay out the other instances like this** (`layOutOtherInstances`, asks first) copies an instance tab's layout to the block's other instances in the model — any block, from a template or not; tab names kept. **A template's attached layout** (step 11c-2): `readTemplateLayouts` reads the `attachments.excel` of the canvas templates a loaded workspace or `.fmide` document carries (a system file carries none), each through `cleanModuleLayout` and only for its template's own family; `applyModuleLayouts` uses it for a module with no remembered layout of its own — the version the canvas was made from (`canvas.template.versionId`), else the newest with one (`templateLayoutFor`) — and marks the tab "layout from the template" (`tabLayoutFromTemplate`; an instance layout the same way); changing the tab makes it your own remembered layout. **Attach to Template…** (with fmIDE's window behind, `09f-from-fmide.js`): Layout → 📎 Attach to Template… (`#btnAttachLayout`, picker `#attachModal`, `modulesWithTabs`) and 📎 Attach on a module's or instance tab (`.module-attach`) send fmIDE `excel:attach-layout`, a module layouts file of one entry (`moduleLayoutNow`: the model's tabs now, cleaned); fmIDE asks and answers in words, shown in `#moduleLayoutsStatus`; test group 75. The Tabs panel marks a module's tab (`.module-tag`, **Forget**) and an instance tab (`.instance-tag`, Forget, `.instance-copy`), says what a new layout took (`#moduleLayoutsStatus`) and has Export / Import Module Layouts. Everything read goes through `cleanModuleLayout`. Step 11b left fmIDE unchanged, but for the layouts file version its Attach Excel layout… accepts (`EXCEL_MODULE_LAYOUTS_VERSION`).
