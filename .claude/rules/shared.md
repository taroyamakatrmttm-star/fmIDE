# Shared code (`src/shared/`)

Loaded when a session works on the shared modules or the build. Moved word for word from `CLAUDE.md` (12 October 2026); keep it in step with the code, as `CLAUDE.md` asks.

- **Shared code lives once in `src/shared/`** and is pulled into both apps by a line `// build:include shared/<file>.js` inside a script piece (indented like the marker). **Its files are real modules** (step 3c, `docs/step3-modules.md`; `src/shared/package.json` says `"type": "module"`): each imports what it uses from the others — one line each, `import { a, b } from './other.js';` — and exports what anything else uses — `export function` / `const` / `let` / `class`, no other form; Node tools and tests `require()` them as they are (Node 22.12 or later), and the build (`moduleFragment` in `tools/build.js`) leaves the import lines out and takes the `export ` off, so the apps get exactly the plain fragments they had; it stops when a name imported isn't exported or an app doesn't include a file its modules import. **A shared file using another's name must import it** (test group 64 fails otherwise: the apps share one scope and would not notice). Today: `escaping.js` (escapeXml, safeNum, safeColor), `input-rule.js` (the input-rectangle rule, and `reachesOutsideTimeline` — when a rectangle's source needs a period outside the timeline), `format-roles.js` (fmIDE only since step 11a: the two canvas roles, Inputs and Calculations, and their defaults), `file-formats.js` (shared kinds, versions, upgrades — among them `dropExcelOnlyPresets` / `dropExcelOnlyNodeStyles`, step 11a — kind inference, and `FILE_LIMITS` — `fileTextProblem` / `fileDataProblem` refuse a file opened that is over 50 MB, nested over 100 levels or holding over 5 million values; never applied to the autosave), `fmide-files.js` (fmIDE only, and the pack checker: `FILE_FORMATS` — every kind fmIDE reads, its version, label and where it opens — `FMIDE_FILE_MIGRATIONS`, the reader `readFmData`, and the checks on templates, recipes and library functions from files: `isTemplateUid`, `cleanRecipeData`, `cleanLibraryFunctions`, `readLibraryPackData`, and `readLibraryIndexData` for the library's list), `library-pack.js` (a library pack's details and their checks, `cleanLibraryPackInfo`, the accepted licences, and the checks on an entry of the library's list, `cleanLibraryIndexEntry`; fmIDE only for now), `store.js` (browser storage, below), `update-notice.js` (the "new version is ready" notice, `watchForUpdates`), `file-picker.js` (`letAnyFileBePicked`: on an iPhone or iPad — Safari greys out `.fmide`, a type it doesn't know — the file boxes that take one lose their `accept`; all three apps), `help-panel.js` / `help-panel.css` (the Help panel, step 10, `createHelpPanel`), `phone.js` / `phone.css` (step 17, fmGraph and fmIDE; ExcelExporter uses only `phone.js`'s phone check and `shareFiles`, P3: `isPhoneScreen` — a touchscreen whose screen's shorter side is under `PHONE_MAX_SIDE` 600 — `canVibrate`, `tick`, `fineStep`, `shareFiles` (the share sheet, else a download), `keepScreenOn` (Wake Lock) and `createPhoneSlider`, the phone's own slider: grabbed anywhere without a jump, finer by moving the finger up (`FINE_STEPS`), a notch at the base with a tick, round marks ticking, − / + repeating, typing, double-tap to the base, the keys, `vertical` for a fader (sideways is finer); each finger by its own pointer id; touches nothing until called, so Node loads it), `pointer-input.js` (mouse, finger and pen, step 9: `onPress`, `followPointer`, `pressDefault`, `isEmulatedMouse`, `waitForHold`, double-tap, `body.touch-input`; moved out of fmIDE in 9c for ExcelExporter's Tree view, by the owner's decision), and the formula IR (step 7): `operators.js` (the operator catalogue, by lasting id; phase E1 added `period`, `if`, `=`, `≠`, `and`, `or`, `not`, `round`, `roundup`, `rounddown` — `if` and the rounding ones take named inputs by `toPort`; comparisons use `approxEqual`, rounding `roundLikeExcel`; phase E2a added the one-input `ln`, `exp`, `sqrt`, `int`, `trunc` — a non-finite result is a `math-error`, INT and TRUNC on the number as stored, as Excel; phase E2b `choose` — `index` then `choice 1`… (`choices`, `operatorPortNames`, `chooseChoiceCount`, at most `CHOOSE_MAX_CHOICES` 254), read like `if` through `branches` and `pick`, an index picking nothing `choose-out-of-range`), `uom.js` (units of measure), `functions.js` (function plugins: `parseFunctionText`, our own parser — never `eval` — plus `compileFunctions`, `runFunction`, `functionUnit`, `functionsUsedBy`) and `ir.js` (`compileModel(system)`, `evaluateModel(ir, options)`, `unitOf(ir, canvas, node, path)`, `plugsOf` / `plugLinks`) — both apps calculate from them: fmIDE evaluates the IR, ExcelExporter writes its formulas from it. How each operator is spelled in Excel stays in ExcelExporter (`src/excel-exporter/formulas/operator-spellings.js`, keyed by catalogue id; a test checks every operator has one). Change shared behaviour there, never by copying it into one app; where the apps must differ, the shared function takes a parameter.

- Real modules (step 3c; module folders `src/shared/`, ExcelExporter's `js-head/` and `formulas/`, fmIDE's `modules/`): test group 64 (`tests/64-shared-modules.spec.js`, `npm run test:shared-modules`): each module loads on its own (in Node, the browser's own in a page) and offers what its export lines name, a module uses another's names only through an import, the apps carry each module without its imports and exports, the build's one form of import and export and its messages. Group 65 (`tests/65-modules-in-node.spec.js`, `npm run test:modules-in-node`): the pieces of the apps that are modules, tested alone in Node — the Excel writer (read back by ExcelJS and JSZip), ExcelExporter's formula building (a small model's cells, another tab, helper columns, a row left out, a Constant, sheet names and row keys) and fmIDE's expression parser (`evalExpression`, `readNumber`, `readBool`; fmIDE's `evalExpr` / `evalNumber` / `toBool` hand it `lookupVar` and `fail`).
