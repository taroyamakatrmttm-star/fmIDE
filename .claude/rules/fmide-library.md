# fmIDE: library packs and browsing the library

Loaded when a session works on library packs. Moved word for word from `CLAUDE.md` (12 October 2026); keep it in step with the code, as `CLAUDE.md` asks.

- **Library packs** (step 8 phase 8a, `11e-library-packs.js`, actions in `14c-actions-library-packs.js`; `docs/step8-community-library.md`): a file of templates, recipes and functions to share (`fmIDE-library-pack`), with `pack` details — id, title, author, licence (only `CC-BY-4.0`), description, tags, date. **Save as Library Pack…** (`fm.saveLibraryPack`) adds what items need (a recipe's parts, the functions a function calls); **Open Library Pack…** refuses a pack without valid details, then previews each item's status (`libraryPackItems`: new, present, new-version — a family you have, which linked canvases will offer as an update — or same-name) and adds only the ticked ones and what they need, by the usual import rules (`addMissingTemplates` / `addMissingFunctions`, whose "already here" checks are `templateAlreadyHere` / `functionAlreadyHere`). `fm.previewLibraryPack`, `fm.openLibraryPack` (items by key, `t0`, `f1`). The author name is remembered in your own UI settings (`ui.libraryAuthor`), never taken from an imported workspace. A pack is saved named after its id (`libraryPackFileName`), the name the library requires. **Share in the Community Library…** (`shareLibraryPack`, `showShareLibraryPack`, also opened after saving a pack; a customised ribbon got it once, `ui.libraryShareAdded`) gives the steps and **Open the upload page ↗**, which only opens the library's GitHub upload page (`LIBRARY_UPLOAD_URL`) in the browser — fmIDE sends nothing; the help topic `share-library-pack` (fmGraph's `share-library`) explains every step for someone who knows nothing about GitHub. The File tab's Library group got both commands once (`ui.libraryPacksAdded`). Macros are never shared. **Browsing the library** (8d, `11f-library-browse.js`; actions in `14c-actions-library-packs.js`): File → Library → **Browse Library…** reads `library/index.json` from fmIDE's own site (`readLibraryIndexData`; entries failing its checks are left out and counted), with search, tag and "holds" filters, sorting, a pack's details ("In your library" by `versionId`) and **Preview and add…**, which fetches `library/packs/<id>.fmide-pack.json` (address built from the id only; `credentials: 'omit'`, `redirect: 'error'`, sizes capped while reading), refuses it unless it is exactly the list's size and SHA-256 and carries the list's id, then hands it to `openFmFileText` → the Open Library Pack preview (`showLibraryPackPreview`): nothing is added without it. Only where the page links a manifest (`libraryOnSite()`, the `site/` build): the single file says where the library is and makes no request. Offline, or a site without a library: a message, no change. Nothing is cached (the service worker leaves `/library` out). `fm.listLibrary`, `fm.previewLibraryPackFromLibrary`, `fm.addFromLibrary` return Promises and are `macro: false` (not in the Macro Builder or Command Launcher, refused inside a macro, never recorded). A customised ribbon got Browse Library… once (`ui.libraryBrowseAdded`). **Where items came from** (8b): each template or function version added from a pack gets `origin: { packId, packTitle, author, licence }` — the one it carries (shared before; packs v2 keep it, for the CC BY credit) or the pack's (`packItemOrigin`). Read through `cleanItemOrigin` (`src/shared/library-pack.js`; a bad one is dropped whole), kept by `templateEntryFrom` / `templateRecord` and `cleanLibraryFunctions` (the library's reader; `cleanFunctionDefinitions` drops it, so a model — system, module, `modelFunctions` — never carries one). New versions you save have none. Shown in the Templates window and Functions manager (`originLines`), "Update this canvas" and the pack windows. The family rule (`familyAuthorWarning`): a pack adding a version to a family with a version from another author, or without an origin (your own), is warned about — compared with the pack's author (`sameAuthorName`), never an item's claim — and starts unticked.
